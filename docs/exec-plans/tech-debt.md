# Technical debt register

Status: canonical | Owner: engineering | Last verified: 2026-08-11 (commit `3630977`)

Accepted debt **is** recorded. Every entry carries an ID, impact, owner, governing spec,
reproduction or evidence, intended resolution, and a review trigger. A TODO comment without a linked
debt or plan ID fails policy.

Debt here is work that was consciously deferred with a known cost. Absent product capability —
including missing brief features — belongs in [known gaps](../quality/known-gaps.md) instead.

| `DEBT-012` | An attendee itinerary is addressed by a capability URL, which leaks the way URLs leak: browser history, referrers, screenshots and shared screens can disclose it, and anyone holding it can read and edit the plan. No revocation or rotation is provided because the payload is deliberately limited to starred public-session slugs; the anonymous shareable URL keeps the public API credential-free. Empty mints are pruned after 24 hours and all plans after the event ends plus a full UTC-day grace. Adding a name, an email address, a ticket, a payment, or any non-public data to an itinerary requires revisiting identity, retention and revocation before that field ships | publishing | `PRD-PUB-001`, `ACC-PUBLIC` | Re-review before any itinerary contract or schema change; identity plus revocation/rotation must ship before the payload crosses the named public-data boundary | #123 |
| `DEBT-013` | **A decision notification is sent to an address nobody verified.** A CFP proposal's submitter address is an answer typed into an unauthenticated public form; nothing proves the person who typed it owns it. Until issue #66 that was inert, because the address was only ever stored — this change is what makes it live, so the trade-off is accepted here rather than inherited. An organizer's accept/decline decision therefore reaches whatever address the applicant entered, including one they entered for somebody else. Bounded: it takes an authenticated organizer acting deliberately, it is one message per proposal per outcome, and the message carries only the fact of the decision. **This is acceptable while that stays true. It stops being acceptable the moment a decision notification carries reviewer comments, scores, or anything else an applicant would not want a stranger to read** — at that point an unverified address is a disclosure of somebody's review, and the address must be verified before the message is enriched. Deliberately *not* accepted on the public submission path: a confirmation there would make the form a mail-bombing primitive at the submission throttle's ~14k/day per source address, so no CFP submission confirmation was shipped | communications-integrations | `PRD-COM-001`, `PRD-CFP-002` | A decision notification is sent only to a verified address, or the applicant confirms the address before any decision is delivered; the enrichment guard above is what triggers this | #66 (accepted), #132 (verification) |

## Review trigger

Re-review this register whenever an `ACC-*` row changes verdict in the
[quality scorecard](../quality/scorecard.md), and before any release claim. A closed row is kept for
one further review cycle so the deferral is auditable, then removed.
